# R18 — repair compressed MZ worker startup

R17's Go installer and JS plugin understood POR .jsono, but the Python Service still called game_root(), which required System.json and raised IA_SOLAMENTE_RPG_MV_MZ. The old diagnostic classified that error generically. The supplied startup-status confirms the generic error and the submitted installed binary matches its owner marker. The worker now recognizes the same bounded MZ POR profile, including active loader registry, expected files, and a Base64-shaped compressed System marker. No arbitrary game JavaScript is executed and no source game files are written. Root and www layouts are both covered; unknown extensions, inactive loaders and ambiguous paths still fail closed.

The startup diagnostic preserves specific safe layout categories and reports a separate cache error without exposing raw paths, tokens or dialogue. Both Windows probe tools now find the actual MV/MZ bridge layout.

Tests cover authenticated HTTP service on .jsono-only root and www fixtures, cache integrity, invalid profiles, and regression checks. The Windows release gate now creates a synthetic MZ game using the actual LZString library (CI only), installs the new EXE, verifies real English and Japanese OPUS responses from the new worker, and verifies the installed plugin's localized dialogue, choices and popup presentation via the synthetic runtime. It must not create a System.json. No commercial game files, text, executable or models from the user's upload were published. Actual game-runtime acceptance remains separate; earlier R17 did not exercise the packaged worker on .jsono-only MZ.
