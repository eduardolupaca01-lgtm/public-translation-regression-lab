# R45 Fix2 — eliminate render-thread I/O and report native scan progress
User evidence: verified previous installation emitted BOOT_INICIADO, HOOKS_LISTOS, MOTOR_INICIADO and MOTOR_CONECTADO. The local status contained accepted and rejected requests; those are request counters, not a verified total or displayed count. Windows OS error 5 is access denied, with a subsequent successful install; its exact failing OS call was not recorded. 
Fix1 performed synchronous foreground HTTP requests up to 12 seconds per uncached native text, potentially repeatedly while Ren'Py evaluates screens. Fix2 modern client never performs I/O in a game text callback; one background translation queue prioritizes visible text and preserves fairness for native AST scan. Negative outcomes are remembered within the session; transient transport failures retry at most three times. A bounded main-thread periodic callback refreshes still-current native objects with completed results, avoiding global screen restart. Native AST includes default translation blocks, menus and additional_strings; dynamic text is discovered as encountered. Inventory is a count of distinct eligible strings seen, not every possible dynamic utterance. Queue safety bound 100000; saturation explicitly reported. Unknown strings can temporarily appear in original language while OPUS works; not a promise of immediate translation. Limits and counts use only local data. The client publishes counts in a separate lightweight background heartbeat. Servidor's RenPy panel refreshes them automatically, without scanning game files on its timer. RenPy worker only uses 1–2 CPU threads and below-normal process priority for modern client. RPG and WEB behavior unchanged. Installation publishes only verified new staging directories with bounded retries on Windows 5/32/33; does not override OS protections. Exact released Fix1 ownership hashes are allowed for recovery; copy existing database/WAL into a verified new sidecar after restoration, retaining original backup. Test actual native object refresh via RenPy pause on 7.3.2 and real OPUS, plus stress test of 1000 cache misses with no network. Classic adapter currently retains earlier synchronous behavior; this change targets modern runtime and actual reported game; classic regression suite remains mandatory. No user archives or dialogue uploaded. References: https://www.renpy.org/doc/html/screens.html ; https://opennmt.net/CTranslate2/performance.html ; https://learn.microsoft.com/windows/win32/debug/system-error-codes--0-499- .

## Follow-up: independent progress view and stronger acceptance
The first nonblocking change passed all ten pre-build jobs. Add a Ren'Py-only Win32 worker progress window, shown without activation and never topmost; closing the view does not stop the translator. It reads only local aggregate progress and updates at most every 750ms. Rate-limit worker status writes, preserving SQLite commits and swallowing only diagnostic publication failures. The native 7.3.2 fixture now requires discovery of unvisited archived Say/Menu strings, 200 real native Text constructors with the worker absent, automatic real worker connection, actual independent window presence and its independent close, and live native Text refresh during interactions. No fake progress or translation counts. No changes to RPG/WEB worker dispatch.
