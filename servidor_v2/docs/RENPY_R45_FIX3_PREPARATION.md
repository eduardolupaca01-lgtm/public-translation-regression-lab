## Fast-start memory and required preparation acceptance
The preparer publishes a bounded local fast-start JSONL snapshot from accepted translations. It is keyed to the same model-file fingerprint as persistent SQLite; the native client independently validates the exact protected control sequence on every row before use. No network or SQLite DLL is required to read it before hooks activate. The snapshot is limited to 32 MiB and 65,536 rows; authoritative SQLite retains all accepted results beyond that bound. Scan counts include already prepared eligible strings, and progress reports archived/loose script entries, distinct strings, pending, memory reuse and unchanged results. The 7.3.2 source test now invokes the native registered command with a pre-existing cancellation request and requires its ticket-specific result without entering gameplay. The final packaged acceptance invokes actual Servidor --renpy-prepare, requires the queue to drain with real OPUS and an unvisited archived sentence to be in SQLite, verifies its very first native Text construction is already translated before waiting for the live worker, then tests dynamically discovered text and restoration. A full release remains gated on those tests.
