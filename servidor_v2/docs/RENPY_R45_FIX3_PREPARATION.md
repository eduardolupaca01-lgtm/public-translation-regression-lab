# R45 Fix3 — native pre-play inventory and independent preparation
The target is the existing RPG workflow adapted to Ren'Py: discover known visible text before playing, prepare its persistent translations, and handle remaining dynamic text asynchronously. Existing Fix2 preflight jobs passed; the full real packaging run was still executing when this new requirement was incorporated.
- Native loaded script/translation registry, named AST, recognized SL2 displayable arguments and presentation-related Python calls are read without executing arbitrary expressions or extracting/pickling RPA in an external interpreter. The native loader reports loose/archived script-file entries separately. Dynamic expressions, custom formats, image lettering, voice, and unsupported screen constructs cannot be certified by a static scan; they remain runtime or separate-workflow targets. No claim of exhaustive coverage.
- The Windows GUI's existing install confirmation now explicitly includes pre-play preparation for modern profiles. After a verified install, the same original game EXE runs a dedicated registered native command with an isolated save directory, a random local ticket and a separate worker. No gameplay label is entered. The progress view closes to cancel this explicit preparation, retaining completed memory. Ordinary play remains nonblocking and uses normal game launch, no play button. A separate CLI --renpy-prepare is provided for testing/repeating. A stalled or incomplete scan reports incomplete; no fake success. Classic profiles are unchanged; their equivalent separate pre-play command needs version-specific validation.
- Quality guards and OPUS models retained. Static prep drains recognized queue; unchanged/QA-rejected text is not falsely counted as translated.
- Research: https://renpy.org/doc/html/translation.html ; https://renpy.org/doc/html/cli.html ; https://github.com/renpy/renpy/blob/7.3.2.320/renpy/sl2/slast.py ; https://github.com/renpy/renpy/blob/7.3.2.320/renpy/arguments.py .
- New tests verify archived screens/notifications/unvisited dialogue, explicit presentation literal selection, no internal code or input default capture, and rejection of preparation without owned hook. Final end-to-end command acceptance must still be verified before delivery.
