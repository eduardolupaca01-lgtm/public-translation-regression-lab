# R36 — reemplazo de recursos VX Ace en Windows

Incidencia real R35: IA_VXACE_REPLACE_ATOMIC_FAILED después de detectar VX Ace y preparar Game.rgss3a (~842.374 KiB). El error histórico descartaba el código de Windows al fallar os.Rename. La causa exacta en el equipo del usuario (permiso, atributo de solo lectura, archivo abierto u otra) no es identificable retrospectivamente.

R36 conserva el respaldo y el recibo PREPARED antes de publicar. Se verifica SHA-256 de la copia temporal y del destino inmediatamente antes de cada intento; nunca se trunca, borra o mueve aparte el original para forzar el reemplazo. Windows utiliza MoveFileExW con REPLACE_EXISTING y WRITE_THROUGH dentro del mismo directorio, admite rutas Unicode largas y reintenta hasta seis veces ante errores de acceso/compartición transitorios. Solo en el archivo de la copia verificada se retira temporalmente el atributo de solo lectura y se repone; no se alteran ACL ni se cierran procesos ajenos. Si falla, se conserva el registro para recuperar y se informa el código Win32 sanitizado (5/32/33 u otro). Las operaciones de instalación y recuperación utilizan la misma función.

Pruebas de regresión: hash preparado incorrecto, cambio externo durante el reintento, rechazo de bloqueo Win32 persistente y resolución de bloqueo Win32 liberado, instalación y recuperación de recurso con atributo de solo lectura. El paquete final debe superar además un archivo RGSS3A real sintético con solo lectura y toda la suite previa, incluidos SOLData, JSONO, MV/MZ, nombres multilingües y RGSS3A de 1,2 GB. El motor OPUS, la presentación y los límites anteriores no cambian. La prueba del juego real sigue pendiente. No sobrescribir una instalación previa: conservar la copia del fallo y utilizar una copia original cerrada. Referencia Microsoft: https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw
