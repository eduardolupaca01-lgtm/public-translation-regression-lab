# Servidor R44 — MV / NWBin laboratory (no release)

Base: approved R43 commit `9a5376b3fc89bb1eca288fe1820aa5aae008ef9c`; existing R43 and R42 branches are not changed. The supplied layout has six RPG Maker MV core files, plaintext JSON database files, and an index that invokes two compiled binaries via NW.js before main.js. The ordinary installer and worker both expect a plaintext js/plugins.js. A different engine is not required.

## Stage 1

- Detect the narrow observed MV/NWBin layout read-only, with explicit diagnostics for missing manifest, malformed/ambiguous resources, and an unavailable supported add-on route. Check the original package.json main entry against the selected root. No opaque binary inspection beyond presence and bounded size, execution, extraction, rewriting or replacement.
- Laboratory profile: an application maintained by its publisher can independently expose a standard plaintext add-on registry that its original HTML already loads after both compiled binaries and before main.js. This test contract uses an explicit `// IA_NWBIN_ADDONS_V1` marker and the ordinary PluginManager.setup($plugins) boot path. It is not an existing NW.js feature or evidence of permission in a third-party title. The marker is for an author-prepared profile only, not an instruction to manufacture a missing registry or edit a protected title's launch code. For such an intentionally prepared profile the existing MV installer can register IA Traductora and restore the exact original registry; its worker and plugin still use their original checks. All opaque binaries, index.html, main.js, package.json and data remain unchanged. An application without the supported original add-on entry remains blocked.
- Synthetic Go tests check detection, manifest, original resource hashes, install and recovery for the publisher-prepared profile. A separate Windows test downloads the official NW.js 0.48.4 SDK, verifies its published SHA256, compiles two independently authored laboratory scripts with nwjc, and launches the native SDK with its synthetic app. It checks that both binary scripts execute before an installer-owned harmless add-on, then verifies exact restore. The SDK version is a period-representative laboratory choice, not identification of the supplied game's precise version. The actual translator and OPUS are not executed in that native loader test; existing R43 presentation tests continue to run unchanged.
- No new runtime/model/translation cache schema, no R44 distributable or support claim for the submitted title at this stage. Need the actual original package.json and evidence of a supported add-on/localization interface. If the game checks integrity and rejects extra code, do not interfere with its checks. Plaintext data can be studied separately for supported localization exports. No supplied game code, binary or data is committed.
